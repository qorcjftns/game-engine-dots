# 개발 순서와 완료 기준

## 기준 상태와 선행 조건 — 2026-10-25

이 계획 작성 시점의 main은 PR #5까지의 문서 코어 단계입니다. [PR #6](https://github.com/qorcjftns/game-engine-dots/pull/6)과
[PR #8](https://github.com/qorcjftns/game-engine-dots/pull/8)은 아직 미병합이며, 이 계획은 PR #8 검토본을 기준으로 합니다.
다음 기능 구현은 **PR #6 → #8의 main 병합 후 최신 main에서 시작**합니다.
이번 변경은 계획 문서만 다루며 M2 기능이 구현됐다는 뜻은 아닙니다.

첫 마일스톤 M1은 프로젝트 생성·열기 → PNG 배치 → 이름·위치 수정 → 드래그·undo/redo → 저장·재열기입니다.
PR #8 검토본에서 이 흐름과 미저장 변경의 저장·버리기·취소를 macOS/Retina 200%에서 확인했고,
Mac·Windows CI도 통과했습니다. 자세한 근거는 [검증 기록](verification.md)에 있습니다.
Windows 실제 GUI·DPI와 macOS Dock Quit·운영체제 강제 종료는 이 확인 범위에 포함하지 않습니다.

## M2 목표: 같은 실행 세션에서 공동 편집

GUI 한 개가 열고 있는 프로젝트 한 개를 사람이 GUI로, 에이전트가 CLI·MCP로 함께 편집합니다.
이미 구현한 개체 추가·삭제, 이름·위치 변경, undo/redo와 저장을 같은 명령 경로에서 사용합니다.
타일맵보다 이 연결을 먼저 완성해, 이후 추가할 편집 기능도 두 사용자가 함께 활용할 기반을 만듭니다.

**완료 시나리오:** GUI로 PNG 프로젝트 열기 → 에이전트가 현재 장면 조회 → 이름·위치 변경 →
GUI 즉시 반영 → 사람이 undo/redo → 같은 세션에서 저장 → 종료·재열기 후 결과 확인.

## 구현 PR 1. 공통 계약과 읽기 전용 CLI

프로젝트·장면·개체 조회와 기존 편집 명령의 공통 입출력·오류 계약을 정리합니다.
CLI에는 우선 저장된 JSON의 검사·조회만 추가하고 기존 info·viewport 계약을 유지합니다.
아직 실행 중인 GUI의 저장 전 상태를 읽는 기능으로 설명하지 않습니다.

**완료 기준:** CLI로 실제 프로젝트의 개체 ID·이름·좌표·리소스 참조를 조회하고,
잘못된 문서를 구분하며 파일을 수정하지 않음. 출력에서 디스크 조회임을 식별할 수 있음.

## 구현 PR 2. GUI가 소유하는 세션 연결과 조회

GUI가 문서를 계속 소유하고 외부 요청을 직렬로 처리하는 로컬 연결을 만듭니다.
CLI가 실행 중인 세션에 연결해 저장 전 문서 상태와 편집 가능 여부를 조회합니다.
구체적인 통신 방법과 의존성은 macOS·Windows에서 작은 검증 후 선택합니다.

**완료 기준:** 디스크 값과 다른 저장 전 문서 값을 CLI에서도 확인.
세션 종료·연결 실패를 구분하고, 프로젝트를 다시 열거나 앱을 재시작하면 새 session ID를 사용함.
큐에서 만료된 요청을 나중에 적용하지 않는 처리와 요청 결과 조회의 기반을 확인.
요청 처리를 화면 그리기에만 묶지 않고, 창이 최소화·가려진 상태에서도 조회·허용 명령의 기한 내 응답을 검증.

## 구현 PR 3. 기존 편집·이력·저장 명령의 CLI 연결

기존 스프라이트 편집 명령과 undo/redo·저장을 실행 중인 GUI 세션으로 전달합니다.
확정 전 속성 입력, 드래그, 대화상자 중에는 변경을 거부하고 현재 작업을 보존합니다.
에이전트 변경도 GUI의 선택·캐시·미리보기·dirty와 같은 이력에 반영합니다.

**완료 기준:** CLI 변경을 수동 재열기 없이 GUI에서 확인하고 한 번의 undo로 해당 명령 복원.
GUI에서 저장 지점으로 undo하면 clean이 되고 redo하면 dirty가 됨.
오래된 revision·다른 세션·편집 중 요청·중복 request ID를 검사하며,
저장 실패에도 열린 문서·파일·이력을 보존함. CLI가 프로젝트 파일을 직접 덮어쓰지 않음.

## 구현 PR 4. MCP 어댑터와 교차 검증

[공식 Rust MCP SDK rmcp](https://github.com/modelcontextprotocol/rust-sdk)의 stdio 어댑터가 같은 세션 서비스를 호출하게 합니다.
MCP에 별도 편집 규칙을 만들거나 CLI 출력 문자열을 재해석하지 않습니다.
SDK 버전과 별도 크레이트 수는 이 구현 PR에서 검증 후 정합니다.

**완료 기준:** 실제 MCP 클라이언트의 초기화·도구 목록·조회·편집 호출 확인.
위 완료 시나리오를 CLI·MCP 각각 수행하고 저장된 JSON·GUI·재열기 결과를 비교.
Mac·Windows CI와 실제 네이티브 실행·화면 확인은 별도 근거로 기록.

## 함께 지킬 적용 규칙

- session ID는 다시 열기·재시작 시 교체합니다. revision은 세션 안에서 단조 증가하며 undo로 되돌리지 않습니다.
- 변경에는 대상 session ID·예상 revision·request ID를 사용합니다. 오래된 상태에 대한 수정은 거부합니다.
- 변경·undo/redo·저장 요청은 확정 전 입력 변경·드래그·대화상자 중 `editor_busy`로 거부합니다. 입력을 대신 확정하거나 버리지 않습니다.
- 큐에서 대기하다 deadline이 지난 요청은 적용하지 않습니다.
- 이미 적용한 뒤 응답을 잃은 경우는 미적용 실패와 다릅니다. 같은 request ID로 결과를 조회하고 중복 적용을 막습니다.
  결과를 모른 채 새 ID로 재시도하지 않으며, 같은 ID에 다른 요청 내용도 허용하지 않습니다.
- 파일 저장은 GUI가 소유한 같은 세션에서만 수행합니다. 별도 프로세스의 직접 파일 쓰기는 지원하지 않습니다.

## 역할과 진행 순서

총괄은 방향·범위·작업 배분·완료 기준과 리뷰만 맡고, 모든 수정을 서브에이전트에 위임합니다.
공통 계약 담당이 PR 1을 준비하는 동안 GUI 담당은 로컬 연결과 입력 중 상태를 검토하고,
검증 담당은 실패·재시도 시나리오를 준비할 수 있습니다.
공용 API 합의와 세션 연결 → 편집 적용 → MCP 연결은 의존 순서대로 진행합니다.
한 파일의 작성자는 한 명으로 정하고, 각 PR에 관련 코드·테스트·문서를 함께 묶습니다.
