# 개발 순서와 완료 기준

## 0. 개발 기반 — 현재

- Rust/Cargo workspace, 코어·데스크톱·CLI 경계 작성
- 한국어 설계·역할·에이전트 접근 규약 작성
- 프로젝트 내부 Rust 설치기와 공통 개발 명령 작성
- 정수 배율·고정 틱 코어, CLI, 화면 데모 소스와 검증 코드 작성

**남은 완료 기준:** Rust 설치, 의존성 다운로드, `Cargo.lock` 생성,
포맷 정리, `check` 통과, macOS 데모 실제 실행.
현재는 설치 환경의 네트워크 제약으로 여기까지 확인하지 못했습니다.

## 1. 두 운영체제에서 같은 픽셀 화면

macOS와 Windows x64에서 빌드하고 직접 실행합니다.
960×540, 1001×701, 최소 크기 미만, Retina/디스플레이 배율 변경을 확인합니다.
상하 방향·검은 여백·키 입력·창 재열기·포커스 복귀를 검증합니다.
창이 열린다는 사실만으로 픽셀 품질 검증을 대신하지 않습니다.

**완료 기준:** 두 운영체제의 테스트 결과와 실제 화면 기록.
Git 원격을 정한 뒤 같은 검사를 CI에 연결합니다.

## 2. 작은 게임을 표현하는 공통 코어

프로젝트별 해상도, 장면 파일, 안정된 개체 ID, 스프라이트,
타일맵, 입력 액션, 기본 충돌을 필요한 순서대로 추가합니다.
사각형 데모를 별도 예제로 옮기고, 게임 상태·명령·조회 API를 코어에 둡니다.

**완료 기준:** 작은 방에서 캐릭터를 움직이고 벽과 충돌하는 게임을
프로젝트 데이터로 불러오고 저장할 수 있음.

## 3. 에이전트가 게임을 조작

CLI에 프로젝트 검사·장면 조회·입력 적용·정확한 틱 진행을 추가합니다.
그 공통 기능을 rmcp 기반 stdio 서버에 연결합니다.
창 없는 실행과 픽셀 캡처는 지원할 그래픽 환경을 정해 구현합니다.

**완료 기준:** MCP 클라이언트에서 초기화·도구 목록·호출을 실제 검증하고,
동일한 초기 상태와 명령을 CLI로 재현해 같은 상태와 화면을 얻음.

## 4. 사람이 편하게 만드는 도구

실제 게임 제작 중 반복되는 작업을 보고 장면·타일 편집 UI,
실행 중 속성 검사, 리소스 재로딩, 오류 위치 안내를 추가합니다.

**완료 기준:** 사용자와 에이전트가 같은 프로젝트를 번갈아 수정하고,
사람이 변경 내역을 이해하며 macOS·Windows용 게임을 패키징할 수 있음.
앱 서명·공증·설치 파일은 실행 파일 생성과 별도로 검증합니다.
