# 전체 개발계획과 완료 기준

## 기준 상태와 계획의 읽는 법

이 계획은 main `57b4d2a4`를 기준으로 합니다. M1 GUI 구현과 검증 기록이 main에 포함되어 있습니다.
[PR #9](https://github.com/qorcjftns/game-engine-dots/pull/9)의 M2 계획은 개발 브랜치에 병합되어 main에 포함되지 않았으므로,
이번 단일 전체 계획에 그 방향을 흡수합니다. M2 이후 기능이 구현됐다는 뜻은 아닙니다.
도트 에디터와 대화형 에셋 제작은 사용자가 추가한 통합 제작 경험 요구이며 v1의 새 M7 범위입니다.
기존 M1~M6와 근거리 PR 순서는 유지하고, 애니/HUD·audio·export·통합 인수는 M8~M11로 이동합니다.

현재 근거는 macOS ARM64/Retina의 실제 GUI와 Windows x64 CI입니다.
Windows 네이티브 실행·DPI, Mac Intel·Windows ARM 지원을 완료했다고 쓰지 않습니다.
기능·CI·실기기·패키지·외부 배포의 확인 범위는 [검증 기록](verification.md)과 구분해 기록합니다.

M1·M2는 구현된 기반입니다. M3는 네 PR로 구현 중이며 snapshot·Play·독립 player·CLI/MCP 실행 제어를 연결했습니다.
main과 stacked PR의 반영 상태, 실제 검증 범위는 [검증 기록](verification.md)을 따릅니다.
M4~M11도 사용자 흐름과 완료 조건을 정하되, 실제 API·라이브러리·PR 수는 해당 단계 승격 때 확정합니다.

## v1 완료 정의

사용자가 엔진 소스를 수정하지 않고 다음 흐름을 수행할 수 있으면 v1로 판정합니다.

1. GUI에서 프로젝트·장면·리소스를 만들고 CLI·MCP에서도 같은 편집 세션을 조회·수정합니다.
2. 지원하는 행동 코드 작성 경로 하나로 입력·이동·상호작용 규칙을 프로젝트 안에서 바꿉니다.
3. 도트 캔버스에서 수동 편집하고 에이전트와 대화해 정적 PNG 후보를 만든 뒤 비교·보정·승인하여 프로젝트에 적용합니다.
   기본 충돌·타일 레벨·장면 전환·스프라이트 애니메이션·텍스트/HUD·효과음/BGM과 함께 사용합니다.
4. Play·pause·정확한 tick 진행과 상태·오류 조회로 결과를 확인하고, 편집 원본을 보존한 채 stop합니다.
5. 저장·재열기·이전 형식 전환과 최근 복구 지점의 복원을 확인합니다.
6. 같은 runtime을 포함한 게임 패키지를 만들고, 에디터·저장소·개발 캐시·Rust가 없는 지원 Mac과 Windows 실기기에서 실행합니다.

단일 사용자/로컬 제작 도구를 기준으로 합니다. full IDE·핫리로드·visual scripting·범용 ECS·3D·멀티플레이·
플러그인 플랫폼·모든 물리 효과·모든 CPU/OS 지원은 v1 범위에 넣지 않습니다.
행동 코드 경로는 필수지만 특정 언어와 내장 코드 에디터를 미리 약속하지 않습니다.

## M2: 구현된 공동 세션 네 PR

GUI 한 개가 열고 있는 프로젝트 한 개가 대상입니다. 새 타일맵·게임 실행·원격 서비스는 함께 넣지 않습니다.
세션 계약은 [접근 규약](agent-interface.md)을 기준으로 하고 통신 방법·SDK 버전·크레이트 수는 구현 때 검증합니다.

| PR 단위 | 구현 범위 | 완료 기준 |
| --- | --- | --- |
| 1. 공통 계약·읽기 CLI | 저장된 프로젝트 검사/조회, 기존 명령의 입출력·오류 계약 | 실제 개체 ID·이름·좌표·자산 참조 조회, 파일 무수정, 기존 info/viewport 유지 |
| 2. live 조회 | GUI 소유 세션·직렬 요청·연결 수명·결과 조회 기반 | 저장 전 확정 문서 조회, 새 session ID, 종료/연결 실패 구분, 최소화/가려짐에도 기한 내 응답 |
| 3. live 편집 | 기존 추가/삭제·이름/위치·undo/redo·저장 연결 | GUI 즉시 반영·같은 이력/dirty, stale/busy/중복/저장 실패 보존 |
| 4. MCP 연결 | 공식 SDK stdio 어댑터, 같은 세션 서비스 호출 | 실제 초기화·도구 조회/호출, CLI/MCP 교차 편집→GUI undo→저장/재열기 |

**가정과 선행:** GUI 세션이 문서를 계속 소유합니다. 별도 프로세스의 직접 파일 덮어쓰기는 금지합니다.
입력 중에도 조회는 확정 문서·revision·busy 상태를 반환하되 미확정 draft는 적용된 문서로 내보내지 않습니다.
변경·undo/redo·저장은 draft 변경·드래그·대화상자 중 `editor_busy`로 거부합니다.

revision은 세션 안에서 단조 증가하며 undo로 되돌리지 않습니다. 다시 열기·재시작 때 session ID를 교체합니다.
변경의 request ID로 중복 적용을 막고 결과를 조회합니다. 큐에서 deadline이 지나면 적용하지 않지만,
이미 적용한 뒤 응답을 잃은 경우를 실패로 단정하지 않습니다. 확인 없이 새 ID로 재시도하지 않습니다.

**실패 gate:** stale 요청의 적용, 취소/만료 후 늦은 적용, 응답 유실 후 중복 적용,
사람의 draft 덮어쓰기, GUI를 거치지 않은 저장 중 하나라도 남으면 다음 단계로 완료 처리하지 않습니다.

## M3: runtime 단계의 네 PR

**구현/실험 기록:** [runtime 경계](runtime.md)에 실행 사본·공통 출력·입력·독립 호스트와 bounded 행동 실행 후보 실험을 기록합니다.
네 PR은 #16 → #17 → #18 → 실행 제어 PR 순서이며 선행 M2의 main 반영이 남아 있습니다.

**선행 실험 범위:** 편집 문서와 실행 world의 분리, 기본 camera/renderer 공유, 입력 포커스,
독립 player 호스트를 작은 실행물로 확인합니다. 이 결과로 아래 경계를 확정합니다.
행동 코드의 작성/검증 경로와 실행 격리 후보도 시험해 M4 착수 조건으로 남깁니다.
정상 종료(Dock Quit 포함)의 취소 보존과 강제 중단의 복구 지점/지원 경계도 이 실험에서 점검하기 시작합니다.

| PR 단위 | 구현 범위 | 완료 기준 |
| --- | --- | --- |
| 1. 실행 복사본·공통 출력 | 문서/자산 snapshot으로 runtime 생성, editor와 player가 공유할 renderer/camera 경계 | 시작/stop 반복에도 원문서·저장 파일·편집 dirty 불변, 동일 자산의 픽셀 출력 비교 |
| 2. 입력·실행 제어 | action 기반 기본 키보드/마우스 입력, 고정 tick, Play/pause/step/stop | GUI TextEdit가 게임 입력을 발생시키지 않음, 명시적 N tick이 정확히 진행, focus 상실 처리 |
| 3. 최소 독립 player | 같은 runtime으로 프로젝트/자산을 읽는 작은 실행물 | Mac·Windows 빌드와 실제 지원 환경의 시작/출력 smoke, 에디터 UI 의존 없음 |
| 4. 실행 조회·회귀 | CLI/MCP의 실행 세션 조회·제어·tick/frame 확인 | 같은 snapshot/입력의 상태·화면 회귀, stale 실행 세션 거부, stop 후 편집 재개 |

이 단계의 Play는 씬·입력·시간 진행을 확인하는 기반이며 사용자 행동 코드는 M4에서 연결합니다.
실행 중 편집 문서의 변경은 초기에는 거부합니다. 실행 상태를 원본에 자동 반영하지 않습니다.
실시간 정지 후 따라잡기 정책과 에이전트의 정확한 tick 진행을 구분하고, 후자에는 tick을 임의로 버리지 않습니다.

**실패 gate:** 독립 player가 editor 내부 상태를 필요로 하거나, 두 호스트의 출력/입력 경계가 다르거나,
실행 실패가 편집 문서를 손상하면 먼저 경계를 수정합니다. export 가능성을 M10까지 미루지 않습니다.
기준 기기·부하 장면·60Hz 출력 목표와 메모리/지연 측정 방식을 이 단계에서 정합니다.
지원 CPU·최소 OS 후보와 export 빌드 호스트도 M3 실험에서 1차 선정하고 M10 실기기 검증으로 확정합니다.

## M4~M11: 승격할 때 확정할 작업과 완료 조건

### M4. 행동 코드 작성 경로 하나

- **작업/산출:** M3 실행 호스트 위에 프로젝트 행동 리소스·바인딩·기본 로그와 오류의 소스 파일/줄/연결 개체 근거를 연결합니다.
  사용자가 엔진 소스 없이 규칙을 바꾸는 작성→검증→Play 경로 하나를 제공합니다.
- **선택 gate:** 언어/작성 도구·실행 예산·중단 방법·허용 호스트 API·독립 player 포함 가능성을 비교하는 실험이 먼저입니다.
  특정 언어, full IDE, 핫리로드를 미리 확정하지 않습니다.
- **완료/실패:** 정상 규칙과 문법 오류·무한 루프·런타임 오류를 시험합니다. 오류는 원인과 위치를 보이고 editor/문서를 보존해야 합니다.
  실행을 중단할 수 없거나 export에서 같은 코드를 실행할 수 없으면 후보를 바꿉니다.

### M5. 기본 2D 충돌·물리

- **작업/산출:** static/kinematic/trigger를 기본 범위로 하고 최소 shape·충돌 이벤트·디버그 표시·편집 속성을 연결합니다.
  검증된 라이브러리 사용 여부와 동적 rigid body 필요성은 별도 실험에서 정합니다.
- **완료 gate:** 이동체가 정적 벽과 모서리에서 일관되게 반응하고 trigger 진입/이탈을 중복 없이 관찰합니다.
  빠른 이동, 긴 프레임 뒤 고정 tick, 시작 시 겹침, 장면 교체 시 정리를 검사합니다.
- **범위/위험:** 모든 물리 효과·복잡한 관절·천·물리 편집 전용 도구는 포함하지 않습니다.
  허용 오차와 지원 shape/body를 명시하고 벽 관통·단위 불일치를 방치한 채 타일 충돌로 확대하지 않습니다.

### M6. 타일맵·줌팬·여러 장면

- **작업/산출:** orthogonal 단일 타일 레이어·PNG 팔레트·칠하기/지우기부터 시작합니다.
  줌팬·선택 좌표를 같은 변환으로 처리하고, 장면 목록/참조와 runtime 장면 전환을 연결합니다.
- **완료 gate:** 한 stroke가 undo 한 건이고 저장/재열기·CLI/MCP 편집·runtime 표시가 일치합니다.
  지원 타일 충돌, 음수 좌표/여백/DPI, 없는 장면 참조와 전환 후 자산 수명을 확인합니다.
- **선행/위험:** M3~M5와 새 문서 형식/큰 맵 데이터 실험이 필요합니다.
  복잡한 자동 타일·무한 월드·prefab/상속 체계로 확장하지 않습니다. 데이터 상한·migration을 먼저 확정합니다.

### M7. 도트 에디터와 대화형 에셋 제작

중앙 픽셀 캔버스·도구/팔레트·대화/후보 패널로 구성합니다. 사용자는 원본을 보며 그리거나 수정 요청을 보내고,
후보를 비교·직접 보정한 뒤 적용합니다. 엔진 runtime의 필수 기반은 아니지만 통합 제작 경험을 위한 v1 추가 범위입니다.
실제 선행은 M2 공통 명령과 자산 버전/migration입니다. physics/runtime 완료를 필수 의존성으로 두지 않습니다.

- **7A 수동 편집 gate:** 정적 PNG·단일 캔버스의 import/export, grid·palette·pencil·eraser·사각 선택·zoom과 stroke 단위 undo를 제공합니다.
  GUI와 에이전트가 같은 픽셀 명령·검증·이력을 사용합니다. provider 미연결/오프라인에서도 편집·저장 흐름이 완결되어야 합니다.
- **7B 대화/job gate:** 대화 UI·agent/backend와 bitmap provider를 구분하고 각각 하나의 연결부터 실험합니다.
  prompt·선택한 참조/기준 버전·픽셀 크기·팔레트·선택 영역·스타일을 요청 문맥으로 전달합니다.
  비동기 상태·취소·오류와 지원되는 비용 견적/사용량의 미확정 상태를 구분합니다.
  최초 연결·명시적 job 실행 전 provider·model·비밀값을 제거한 endpoint(전송 대상)·선택 참조/전송 범위·비용 견적 상태를 보여줍니다.
  해당 요청에서 선택한 문맥만 전송하며 프로젝트 전체·키·로그를 자동 전송하지 않습니다.
  취소가 provider 실행/비용까지 없앤다고 보장하지 않으며, 결과 불명 상태를 새 유료 호출로 무조건 재시도하지 않습니다.
- **7C 승인/적용 gate:** 원시 후보를 보존하고 크기·팔레트·투명도 등을 검사합니다. 규격 정규화는 명시적으로 선택하고 결과를 preview합니다.
  선택 영역 밖은 모델의 지시 준수가 아니라 기준 PNG와의 실제 합성으로 보존합니다.
  비교·수동 보정·사용자 승인 뒤 불변 자산 버전을 만들고 예상 버전을 검증하는 공통 명령으로 적용합니다.
  사용 개체·tileset 등 참조와 cache·dirty·undo·저장/재열기를 검증합니다. 프로젝트 undo/redo는 저장된 버전만 오가며 AI를 재호출하지 않습니다.

**보존/실패 기준:** 픽셀 작업 draft·AI 후보·현재 승인 자산을 분리하고 적용 전 scene/runtime은 바꾸지 않습니다.
늦은 결과·바뀐 기준 버전·취소 여부 불명 결과는 후보로만 남깁니다. 미적용 작업의 저장·종료/복구와 프로젝트 적용을 구분합니다.
provider가 지원하는 job 식별·조회/취소 수단과 로컬 요청 상태를 보존해 재시작 후 대조하며, 조회·취소를 확인할 수 없으면 불명 상태로 남깁니다.
provider/model/job·참조/자산 버전·변형·승인 기록을 남기되 권리가 자동 확정됐다고 설명하지 않습니다.
키는 OS 보안 저장소 등 사용자 설정에만 두고 프로젝트·Git·로그·export에서 제외합니다.
한 실제 backend/provider의 정상·오류·취소·결과 유실과 승인 흐름을 확인하며 mock만으로 실연결 완료라 하지 않습니다.

**범위/위험:** full Aseprite·고급 layer·animation timeline을 동시에 만들지 않습니다.
AI spritesheet·8방향·batch 생성·rigging·모든 provider 지원은 초기 범위 밖입니다.
정적 PNG를 먼저 통과시키고 단일 frame 연계는 M8의 프레임 기준/버전 gate 뒤에 검증합니다.
모델이 정확한 픽셀 규격이나 프레임/스타일 일관성을 보장한다고 가정하지 않습니다.

### M8. 애니메이션과 기본 게임 텍스트/HUD

- **8A 애니메이션 gate:** 스프라이트시트 프레임·재생 시간·반복 클립을 편집/저장하고 runtime에서 재생·정지합니다.
  pause/step, 경계 프레임과 없는 자산을 검사하고 CLI/MCP에서도 같은 클립 속성을 사용합니다.
  M7 캔버스의 단일 frame 수정은 frame 크기/위치·기준 자산 버전을 검증하고, 다른 frame과 clip/tileset 참조를 보존한 새 버전으로 적용합니다.
- **8B 텍스트/HUD gate:** 논리 화면 안의 기본 텍스트·이미지/HUD를 프로젝트 데이터와 행동 코드에서 사용합니다.
  프로젝트 폰트/글리프와 export 포함 정책을 정하고 두 OS의 실제 표시를 확인합니다.
- **범위/위험:** 두 하위 gate는 독립 PR 묶음입니다. 범용 UI builder·복잡한 레이아웃/국제화 엔진을 만들지 않습니다.
  프레임 시간·폰트 경로/사용 조건·픽셀 합성의 차이를 검증합니다.

### M9. 효과음과 BGM

- **작업/산출:** 선택한 기본 포맷의 가져오기·참조, 효과음/BGM 재생·정지·반복·볼륨과 행동 API를 연결합니다.
  장치·디코드·자산 수명 실험 후 포맷과 라이브러리를 확정합니다.
- **완료 gate:** 두 OS의 실제 장치에서 소리·반복·pause/stop·장면 전환 후 정리를 확인하고 export에서도 재현합니다.
  장치 없음·누락/손상 파일은 진단하며 프로젝트를 손상시키지 않습니다.
- **범위/위험:** 오디오 제작기·고급 DSP·리듬 게임 수준의 시간 보장은 제외합니다.
  파형 파일의 decode 성공을 실제 재생 검증으로 대신하지 않습니다.

### M10. export와 패키징

- **작업/산출:** M3의 독립 player를 정식 export 경로로 만들고 장면·행동 코드·이미지·폰트·오디오를 묶습니다.
  필요한 자산·버전·실행 안내와 자산/라이브러리의 라이선스·출처 고지를 포함합니다.
- **완료 gate:** 저장소·editor·Rust·개발 캐시가 없는 받는 쪽 기기에서 실행합니다.
  절대 개발 경로·누락 자산·잘못된 타깃/형식 버전을 검사하고 같은 프로젝트 행동을 재현합니다.
  편집용 CLI/MCP 서버를 필수로 요구하지 않고 개발 제어/디버그 기능이 일반 배포 runtime에 자동 노출되지 않음을 확인합니다.
  승인된 로컬 자산만으로 실행하며 대화/이미지 provider나 그 키를 요구하지 않습니다.
- **타깃/위험:** M3의 CPU·최소 OS·빌드 호스트 후보를 실기기로 확인해 지원표를 확정합니다. export 호스트의 Rust/SDK 필요 여부와 최종 게임의 의존성을 구분합니다.
  Mac 한 대에서 양 OS 패키지를 모두 만들 수 있다고 약속하지 않으며 OS별 빌드가 필요할 수 있습니다.
  내부 smoke/ad-hoc 실행과 외부 배포의 서명·공증·채널 검증은 별도 gate입니다. 선택한 채널에 필요한 계정/인증이 없으면 해당 배포는 미완료로 남깁니다.

### M11. v1 통합 인수·안정화

- **작업/산출:** 아래 참조 프로젝트를 처음부터 만들고 행동을 바꾸고 검증·export하는 전체 사용 설명과 인수 기록을 만듭니다.
  앞 단계부터 제공한 로그·상태 검사·migration·복구·성능 계측을 조합해 회귀를 정리합니다.
- **완료 gate:** 지원 Mac/Windows 실기기의 전체 시나리오와 공개된 한계를 확인하고 재현 자료·패키지 버전을 고정합니다.
  실행 전 형식 변환과 최근 복구 지점 복원에서도 마지막 정상 저장본을 보존합니다.
- **범위/위험:** 새 대형 기능을 추가하는 단계가 아닙니다. 필수 gate 실패는 수정/범위 결정 후 재검증하며,
  CI 성공·일부 기능 시연만으로 v1 완료를 선언하지 않습니다.

## 매 단계부터 적용할 품질 gate

- **공통 명령:** M2 이후 새 편집 기능은 GUI와 CLI/MCP에서 같은 자료형·명령·검증·undo를 사용합니다. 실행 제어는 편집 명령과 구분합니다.
- **진단:** 기능 도입 때부터 상태/오류 위치·요청/세션/tick 근거를 남깁니다. Play·pause/step과 기본 runtime 검사는 M3부터입니다.
- **형식/자산:** 첫 형식 변경 PR부터 이전 fixture의 읽기/migration·미지원 미래 버전 거부·실패 시 원본 보존을 검사합니다.
  상대 경로·대소문자·한글/공백·누락/재가져오기·파생 캐시 무효화도 해당 기능과 함께 다룹니다.
- **복구:** 저장은 원자적 교체와 실패 보존을 유지합니다. 새 편집 데이터가 늘 때 복구 지점의 대상·주기·보관과 복원 UX를 정하고 검사합니다.
  강제 종료 복구는 표시한 최근 복구 지점까지를 기준으로 하며, 마지막 입력까지 무손실이라고 약속하지 않습니다.
- **코드 격리:** M3/4 실험부터 허용 호스트 API·실행/메모리 예산·중단·오류 수집 경계를 검사합니다. MCP의 임의 호스트 코드 실행 기능은 제공하지 않습니다.
- **플랫폼/성능:** 포맷·Clippy·단위/IO·통합·CLI/MCP 계약을 양 OS CI로 확인하고 native 창·DPI·입력·장치·패키지는 따로 확인합니다.
  기준 기기와 재현 가능한 부하/입력으로 측정하며 physics 결과의 OS 간 완전한 비트 일치를 가정하지 않습니다.
- **종료:** 새 입력과 일반 앱 종료(macOS Dock Quit 포함)는 미저장 확인·취소 보존으로 보호합니다. 취소할 수 없는 강제 kill/OS 중단은 최근 복구 지점까지의 복원으로 구분해 v1 전 검증합니다.

## 통합 참조 프로젝트와 최종 인수

참조 장면은 엔진 검증 fixture입니다. 작은 게임의 콘텐츠 양이나 완성도를 프로젝트 목표로 바꾸지 않습니다.

1. GUI로 PNG·타일·행동·클립·폰트·오디오를 가져오고 두 장면과 기본 HUD를 구성합니다.
   픽셀을 수동 수정하고 대화형 후보를 비교·보정·승인해 적용한 뒤 원본 복원·영역 밖 보존·provider 없는 실행도 확인합니다.
2. 엔진 소스를 고치지 않고 프로젝트 행동을 바꿉니다. 입력으로 개체를 움직이고 벽과 충돌하며 trigger로 장면을 전환합니다.
3. 애니메이션·텍스트 값·효과음/BGM을 확인하고 GUI와 AI가 같은 편집 결과·이력을 봅니다.
4. 입력 중 busy·stale 요청·응답 유실과 코드 오류를 시험합니다. pause/정확한 tick/frame 조회·stop으로 원인을 확인합니다.
5. 저장/재열기, 이전 형식의 fixture 변환, 최근 복구 지점 복원 후 문서·자산·규칙이 유지되는지 검사합니다.
6. 같은 runtime의 플랫폼별 export를 깨끗한 지원 실기기에서 실행하고 개발 경로/도구에 의존하지 않음을 확인합니다.
7. OS/CPU/DPI·빌드/프로젝트 버전·검사 명령·화면/파일/실제 소리·지원 한계를 기록합니다. 외부 배포는 해당 서명/채널 gate까지 구분합니다.

## 가까운 단계만 상세화하는 계획 관리

각 단계 시작 때 앞 단계 gate·입출력·자산/형식·지원 타깃을 확인하고, 해당 단계와 바로 다음 단계만 구체화합니다.
불확실한 선택은 작은 실행 실험의 산출물·채택 기준·중단 조건을 정해 먼저 확인합니다.

**상세 계획으로 승격할 조건:** 선행 API/자료형의 합의, 선택 실험 결과, 검증 fixture와 실제 대상 환경,
위험·비포함 범위가 정리되어 독립적으로 리뷰/되돌리기 가능한 PR로 나눌 수 있을 때입니다.
M4 이후를 빈 항목으로 남기지 않되, 현재 표의 산출물·gate를 근거 없이 날짜·세부 API·PR 수로 고정하지 않습니다.

현재 PR 작업 계획에는 다음을 적습니다.

- 사용자 문제·완료 시 할 수 있는 일·포함/비포함 범위
- 선행 PR/API·수정 경로/작성자·단계 산출물
- 검사 명령/환경·정상/오류/경합·파일/화면 기준
- 미확정 선택과 실험·실패 시 중단/재계획 조건
- 실제 결과·남은 제한·다음 단계에 바뀌는 가정

범위·형식·의존성·지원 타깃이 바뀌면 코드를 넓히기 전에 이 계획과 관련 문서를 같은 PR에서 갱신합니다.
stacked PR의 선행이 main에 병합되면 후속 base를 적절히 main으로 갱신하고,
완료 판정은 PR의 MERGED 표시뿐 아니라 최신 main에 내용/commit이 실제 포함됐는지 확인합니다.

## 인력·동시 작업·일정 재산정

소유자 1명과 총괄, 최대 3 worker를 기준으로 합니다. 총괄은 방향·작업 배분·리뷰만 맡고 모든 수정을 위임합니다.
일반 배분은 공통 코어/계약, GUI/호스트, 검증/통합입니다. 한 파일의 작성자는 한 명으로 두며 Git·공용 manifest는 통합 담당이 관리합니다.
동시 개발은 주 구현과 계약이 확정된 제한 prototype/검증 등 최대 2영역으로 제한합니다.
M7의 제한 prototype은 선행이 갖춰지면 병렬로 검토할 수 있지만, 새 큰 기능을 동시에 완성하려고 범위를 늘리지 않습니다.
API/형식/선택 실험은 직렬 결정하고, 독립 파일·fixture·OS 검증만 병렬로 진행합니다.

작업 크기는 작은 독립 변경/여러 PR의 기능/불확실한 선택 실험으로 표시합니다.
실제 PR 리드타임·실패/재작업·리뷰 대기·기기 접근·실험 결과를 모아 단계 종료 또는 큰 가정 변경 때 예상 범위를 다시 산정합니다.
현 근거로 완료 날짜나 3 worker가 3배 속도라는 수치는 제시하지 않습니다.
기기·계정·선행 결정이 없으면 그 gate는 미완료로 남기고 독립 작업을 진행하되 v1 인수를 통과한 것으로 쓰지 않습니다.
