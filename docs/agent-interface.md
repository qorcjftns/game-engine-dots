# GUI·CLI·MCP 편집 접근 규약

## 공통 원칙

사람의 GUI 조작과 에이전트의 명령은 같은 프로젝트 문서와 편집 명령을 사용합니다.
편집 명령은 입력 검증·수정·변경 기록을 한 경로에서 처리합니다.
CLI나 MCP에 별도 편집 규칙을 구현하지 않습니다.
선택·확대·패널 상태는 편집 문서와 분리하고, 되돌릴 변경 정보는 명령 설계부터 포함합니다.
열린 문서는 GUI 편집 세션이 소유합니다. 세션 통신을 구현하기 전에는 CLI·MCP가
동일 프로젝트 파일을 동시에 덮어쓰는 편집을 지원하지 않습니다.

## 현재 CLI와 확인 범위

현재 CLI는 코어 설정 조회와 픽셀 표시 영역 계산만 지원합니다.
기존 target/debug 바이너리의 두 응답을 확인했지만 현재 소스 재빌드·계약 테스트 확인은 별도입니다.
프로젝트 편집, 실행 중인 GUI 연결, MCP 서버는 아직 없습니다.

```sh
target/debug/engine-cli info
target/debug/engine-cli viewport 1001 701
```

Windows에서는 실행 파일에 `.exe`를 붙입니다.
stdout은 JSON 한 건, 진단 로그는 stderr, 성공 종료 코드는 0, 입력 오류는 2입니다.
입력 크기는 u32 정수이며 잘못된 크기는 `invalid_window_size`, 너무 작은 크기는 `window_too_small`입니다.
이 규칙은 현재 CLI의 계약입니다. 향후 편집 요청 스키마와 세션 오류는 별도 정의합니다.

## 편집 계약의 도입 순서

1. 프로젝트 문서 단계에서 형식 버전·개체 ID와 명령 입력·결과·오류·되돌릴 변경 정보를 정의합니다.
2. GUI의 스프라이트 추가·속성 수정·드래그를 해당 명령에 연결합니다.
3. CLI에 프로젝트 검사·문서 조회·편집 명령을 노출하고 GUI와 같은 결과를 확인합니다.
4. [공식 Rust MCP SDK rmcp](https://github.com/modelcontextprotocol/rust-sdk)의 stdio 어댑터를 추가합니다.
5. 실행 중인 에디터의 편집 세션을 공유하고 버전 기반 충돌 검출·알림을 연결합니다.

초기 파일 기반 명령과 실행 중인 GUI의 상태 공유는 서로 다른 기능입니다.
각자 파일을 읽고 쓰는 상태를 동시 편집이 구현된 것으로 설명하지 않습니다.
MCP SDK 버전은 구현 시점의 호환성 확인 후 고정합니다.

## 도구와 명령의 후보

아래는 계획이며 현재 MCP 도구가 아닙니다. 입력·출력 스키마는 해당 구현 PR에서 확정합니다.

| 기능 | 목적 | 도입 시점 |
| --- | --- | --- |
| 프로젝트 검사·열기 | 파일 버전·리소스·문서 유효성 확인 | GUI 문서 구현 후 CLI |
| 장면 조회 | 안정된 개체 ID·속성·문서 버전 반환 | CLI 편집 기반 |
| 스프라이트 추가·속성 수정 | GUI와 같은 편집 명령 적용 | CLI 편집 기반 |
| 실행 취소·다시 실행 | 같은 세션의 편집 이력 처리 | 편집 세션 공유 |
| 화면 캡처 | 특정 문서 버전의 픽셀 결과 확인 | 뷰포트 캡처 지원 후 |
| 플레이·틱 진행 | 편집 문서 복사본의 실행 상태 제어 | 플레이 미리보기 이후 |

## 상태와 파일 보호

변경 요청은 대상 문서와 예상 버전을 명시하고 오래된 요청을 거부합니다.
명령 실패 시 문서·이력을 보존하며, 저장은 임시 파일 기록 후 교체로 기존 파일을 보호합니다.
파일 경로는 선택한 프로젝트 기준으로 검증합니다. 임의 코드 실행은 기본 편집 명령으로 노출하지 않습니다.
동시 세션에서는 세션 ID로 작업과 이력을 구분하고, 누가 변경을 소유하는지 명시합니다.

GUI·CLI·MCP의 응답과 저장·재열기 결과를 비교하는 회귀 시나리오를 유지합니다.
문서 수정 성공, 파일 저장 성공, GUI 표시 성공은 각각 별도로 확인합니다.
