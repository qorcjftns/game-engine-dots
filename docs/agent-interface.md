# GUI·CLI·MCP 편집 접근 규약

## 현재 지원 범위와 다음 목표

현재 CLI는 코어 설정 조회와 픽셀 표시 영역 계산만 제공합니다.
프로젝트 편집·실행 중인 GUI 연결·MCP 서버는 아직 없습니다.
첫 GUI 편집 마일스톤은 PR #8 검토본에서 확인했지만 PR #6·#8의 main 병합은 선행 조건입니다.
M2의 네 구현 PR과 완료 기준은 [개발 순서](roadmap.md)에 정리했습니다.

```sh
target/debug/engine-cli info
target/debug/engine-cli viewport 1001 701
```

Windows에서는 실행 파일에 `.exe`를 붙입니다.
현재 CLI의 stdout은 JSON 한 건, 진단 로그는 stderr, 성공 종료 코드는 0, 입력 오류는 2입니다.
기존 계약은 유지하며 새 명령·오류 스키마는 해당 구현 PR에서 확정합니다.

## 문서의 소유자는 GUI 세션

한 GUI가 열고 있는 프로젝트 한 개에 연결합니다. GUI·CLI·MCP의 편집은
같은 문서와 명령 처리 경로, undo/redo 이력, dirty 상태와 저장 서비스를 사용합니다.
CLI·MCP 프로세스가 별도로 프로젝트 파일을 덮어쓰지 않습니다.
프로젝트를 처음 열고 PNG를 가져오는 작업은 기존 GUI 흐름을 사용합니다.

도입 순서는 **읽기 전용 디스크 조회 → 실행 중인 GUI 세션 조회 → 기존 편집·이력·저장 CLI → MCP**입니다.
디스크 조회와 저장 전 문서 조회를 결과에서 구분합니다. 입력 중인 draft는 확정된 문서와 구분하고,
편집 중인지 조회할 수 있게 합니다. 파일을 각자 읽고 쓰는 기능을 실시간 공동 편집으로 설명하지 않습니다.

## 변경 요청과 충돌 처리

프로젝트를 다시 열거나 앱을 재시작하면 session ID를 교체합니다.
문서 revision은 세션 안에서 단조 증가하며, undo로 문서 내용이 돌아가도 과거 revision을 재사용하지 않습니다.
변경 요청은 대상 session ID와 예상 revision을 포함하고 오래된 요청은 적용 전에 거부합니다.

확정 전 속성 변경·드래그·대화상자 중에도 조회는 확정된 문서·revision·busy 상태를 반환합니다.
미확정 draft를 적용된 문서로 내보내지 않습니다. 이때 변경·undo/redo·저장 요청은 `editor_busy`로 거부합니다.
에이전트 요청이 사람의 입력을 강제로 확정·취소하거나 저장하지 않습니다.
다시 조회해 편집 가능 상태와 최신 revision을 확인한 뒤 요청합니다.

허용할 변경은 기존 개체 추가·삭제·이름·위치 명령과 undo/redo·저장으로 제한합니다.
성공한 변경은 GUI 표시·선택·캐시에 반영하고 같은 이력에서 되돌립니다.
저장 실패 시 문서·이력과 기존 파일을 보존합니다.

## 시간 초과와 결과 유실은 구분

변경에는 request ID를 붙입니다. 같은 ID·같은 요청의 재시도는 중복 적용하지 않고,
같은 ID에 다른 내용을 보내면 거부합니다. 세션 안에서 요청 결과를 조회할 수 있게 합니다.
결과 보관 범위와 조회 불가능 시 응답은 구현 PR에서 명시합니다.

- **적용 전 만료:** 큐에서 대기하다 deadline이 지나면 적용하지 않습니다.
- **이미 적용한 뒤 응답 유실:** 클라이언트의 시간 초과만으로 실패했다고 판단하지 않습니다.
  같은 request ID로 상태·결과를 조회하고, 확인 없이 새 ID로 변경을 반복하지 않습니다.

예를 들어 요청 A가 개체를 `(60, 38)`로 옮겼지만 응답을 받지 못했다면,
새 이동 요청 B를 보내기 전에 A의 적용 결과를 조회합니다.
세션이 바뀌어 결과를 확인할 수 없으면 자동 재적용하지 않고 현재 상태를 다시 확인합니다.

## MCP 연결과 검증

[공식 Rust MCP SDK rmcp](https://github.com/modelcontextprotocol/rust-sdk)의 stdio 서버가
같은 세션 서비스를 호출하는 어댑터가 됩니다. SDK 숫자 버전·통신 방법·크레이트 분리는
실제 구현과 두 운영체제 검증 후 결정합니다. 전용 편집 규칙이나 자체 MCP 프로토콜을 만들지 않습니다.

GUI로 프로젝트 열기 → CLI/MCP 조회·편집 → GUI의 즉시 표시·undo/redo → 저장·재열기를 비교합니다.
오래된 revision, `editor_busy`, 큐 만료, 응답 유실 후 결과 조회, 중복 요청, 재열기 후 옛 세션 요청을 검사합니다.
명령 적용·파일 저장·GUI 화면·MCP 연결을 각각 확인하고 미검증 환경은 따로 기록합니다.
원격 네트워크 서비스·임의 코드 실행·다중 GUI 공동 편집은 이번 범위가 아닙니다.
