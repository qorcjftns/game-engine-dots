# GUI 에디터와 엔진 설계

## 제품과 첫 목표

제품은 macOS·Windows용 **GUI 게임 에디터와 자체 2D 도트 엔진**입니다.
첫 목표는 프로젝트 생성·열기 → PNG 스프라이트 배치 → 속성 수정 → 저장·재열기입니다.
실행 데모와 작은 게임은 검증 예제이며 제품 개발 순서를 결정하는 기준으로 삼지 않습니다.

## 언어와 GUI 기반

Rust를 유지해 편집 문서·명령·엔진·CLI를 같은 자료형으로 연결합니다.
단순한 구조체·열거형·함수를 우선하고, 복잡한 제네릭과 자체 매크로는 필요할 때 도입합니다.
코드 식별자는 영어, 설계와 선택 이유를 설명하는 주석은 한국어로 작성합니다.

예정된 `engine-editor`의 GUI에는 [egui](https://github.com/emilk/egui)와
네이티브 앱 실행 기반인 [eframe](https://docs.rs/eframe/latest/eframe/)을 사용하고,
그래픽 출력은 [wgpu](https://wgpu.rs/) 경로를 선택합니다.
창·입력·패널 기반을 재사용하고 자체 편집 문서와 도구에 집중하기 위한 설계 선택입니다.
숫자 버전과 feature 조합은 첫 GUI 빌드에서 확인해 고정하며 이번 계획 변경에서는 의존성을 추가하지 않습니다.

현재 Macroquad 데모는 그대로 유지하고 에디터 주 UI로 확장하지 않습니다.
GUI와 Macroquad를 한 창에 통합하는 작업도 초기 범위에서 제외합니다.
Mac의 DPI·한글 글꼴·입력과 Windows의 디스플레이 배율·실제 창 동작은 별도로 검증합니다.

## 문서·편집 세션·실행 상태 분리

| 영역 | 담는 내용 | 담지 않는 내용 |
| --- | --- | --- |
| 프로젝트·장면 문서 | 형식 버전, 논리 해상도, 개체 ID, 리소스 참조, 속성 | GPU 텍스처, 선택 상태, 패널 배치 |
| 편집 세션 | 현재 문서, 수정 여부, 명령 이력, 되돌릴 변경 정보 | 저장 파일에 불필요한 UI 상태 |
| GUI 상태 | 선택 개체, 확대·이동, 패널 상태, 진행 중 드래그 | 게임 규칙과 별도의 문서 사본 |
| 향후 플레이 상태 | 편집 문서의 복사본에서 만든 실행 상태 | 편집 원본의 직접 수정 |

선택과 패널 상태는 문서 저장·undo 기록과 분리합니다.
플레이·정지는 편집 문서의 복사본으로 실행하여 플레이 중 변화가 원본에 섞이지 않게 합니다.
초기 프로젝트·장면은 사람이 읽고 수정할 수 있는 JSON 텍스트를 우선합니다.
`schema_version`, 안정된 개체 ID, 상대 리소스 경로를 포함합니다.
구체적인 스키마·버전 호환 정책은 문서/저장 구현 PR에서 확정합니다.

## 공통 편집 명령

```text
GUI의 편집 조작 ─┐
CLI의 편집 요청 ─┼→ 편집 세션의 명령 처리 → 프로젝트·장면 문서
MCP의 도구 호출 ─┘                         ↓
                                     조회 결과·변경 기록
```

프로젝트 문서 구현 단계부터 명령 입력·검증·결과와 되돌릴 변경 정보를 설계합니다.
스프라이트 추가·속성 수정 등 GUI 편집은 처음부터 이 명령 계층을 사용합니다.
잘못된 입력은 적용 전에 거부하고 문서와 이력을 유지합니다.
명령은 이전 값·삭제 개체·삽입 순서 등 역적용에 필요한 정보를 보존하고 정·역적용을 검사합니다.
GUI의 드래그 한 번은 변경 한 건으로 묶으며, 최종 undo/redo UI는 후속 PR에서 연결합니다.
GUI 편집 세션이 열린 문서를 소유합니다. 통신 기능을 추가하기 전에는 CLI·MCP가
그 프로젝트 파일을 동시에 덮어쓰는 편집을 지원하지 않습니다.
코어 자료형에는 egui·eframe·wgpu 타입을 노출하지 않습니다.

## 저장과 리소스

프로젝트 생성·열기·저장은 UI와 분리된 서비스에서 처리합니다.
전체 문서를 검증한 뒤 현재 문서를 교체하고, 실패하면 기존 문서·수정 상태를 보존합니다.
저장은 같은 디렉터리의 임시 파일에 기록한 뒤 교체하는 원자적 저장을 기본으로 하며,
실패 시 기존 파일을 보존하도록 macOS와 Windows의 파일 교체 동작을 확인합니다.
외부 PNG는 프로젝트의 리소스 디렉터리로 가져오고 상대 경로로 참조합니다.
파일 IO 오류와 리소스 누락은 위치와 원인을 사용자에게 표시합니다.

## 화면과 시간

GUI 패널과 텍스트에는 일반 DPI와 UI 배율을 적용합니다.
게임 콘텐츠만 논리 픽셀 화면에 합성하고 nearest 필터로 표시합니다.
기본 논리 해상도는 320×180이며 프로젝트별 설정으로 확장합니다.
초기 뷰포트는 정수 배율·중앙 배치를 사용하고 너무 작으면 확대·스크롤 등 명시적 편집 정책을 안내합니다.
창 전체를 저해상도로 그리거나 GUI 글자를 도트 해상도로 제한하지 않습니다.

현재 코어의 60틱 계산과 정수 배율은 런타임 기반 규칙입니다.
장래 편집 뷰포트의 확대·좌표 변환과 실시간 플레이의 시간 진행은 각각 분리합니다.

## 구성 요소와 확장 순서

- `engine-core`: 현재 화면·시간 규칙. 향후 GUI와 독립적인 프로젝트 문서와 편집 명령.
- `engine-editor`: 예정된 GUI 셸·편집 세션 연결·뷰포트. 첫 구현에서 경계를 구체화.
- `engine-desktop`: 현재 Macroquad 출력 검증 데모. 게임 제작 기능의 중심이 아님.
- `engine-cli`: 현재 info·viewport. 이후 공통 편집 기능의 명령 어댑터.
- `engine-mcp`: 이후 공식 SDK를 사용하는 어댑터. 명령 규칙을 복제하지 않음.

GUI 편집 흐름 완성 후 CLI 편집 → MCP → 실행 중인 편집 세션 공유·충돌 검출 순으로 확장합니다.
타일맵·충돌·애니메이션·플레이 미리보기는 그다음 실제 편집 요구에 맞춰 추가합니다.
범용 ECS·3D·멀티플레이·스크립트 언어·복잡한 패널 도킹은 초기 목표에서 제외합니다.
