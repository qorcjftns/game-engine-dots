# 설계와 언어 선택

## 목표

고정된 픽셀 화면 안에서 게임 화면 전체를 그리는 개인용 2D 엔진을 만듭니다.
사람은 실행 화면과 편집 도구를 사용하고, 에이전트는 상태 조회와 명시적인 명령을 사용합니다.
같은 게임 규칙을 두 경로에서 재사용하는 것이 첫 설계 기준입니다.

## 언어 결정: Rust

| 후보 | 이 프로젝트에서의 판단 |
| --- | --- |
| Rust | 네이티브 실행, 명시적 자료형, Cargo의 빌드·테스트 관리가 적합. 소유권 학습 비용은 있음 |
| C++ | 충분히 가능하지만 메모리 수명과 플랫폼별 빌드 관리에 초기 작업이 더 필요 |
| C# | 읽기 쉬운 유효한 대안. 현재는 엔진 코어와 CLI를 Rust 한 언어로 유지하기로 선택 |
| TypeScript | 에이전트 도구와 웹에 유리. 첫 목표인 데스크톱 게임 런타임에는 추가 실행 환경이 필요 |

Rust가 항상 더 읽기 쉽다는 뜻은 아닙니다. 단순한 구조체·열거형·함수를 우선 사용하고,
어려운 제네릭, 복잡한 수명 매개변수, 자체 매크로는 실제 필요가 생길 때 도입합니다.
코드 식별자는 영어, 설계 문서와 판단 이유를 설명하는 주석은 한국어로 작성합니다.

## 초기 화면 라이브러리: Macroquad

창 생성·입력·GPU 출력은 기존 라이브러리에 맡기고,
화면 규칙·게임 상태·장면·명령 처리를 자체 엔진으로 개발합니다.
Macroquad는 [공식적으로 macOS·Windows를 지원](https://macroquad.rs/)하며
[렌더 타깃과 nearest 필터](https://docs.rs/macroquad/0.4.16/macroquad/texture/fn.render_target.html)를 제공합니다.

범용 게임 엔진의 편집기나 게임 모델에 의존하지 않고 출발할 수 있는 작은 기반입니다.
다만 macOS의 그래픽 API 장기 대응, 실제 기기별 DPI, 배포 호환성은 검증해야 합니다.
이후 요구가 커지면 wgpu 기반 출력 등을 검토할 수 있도록 코어에서 Macroquad 타입을 사용하지 않습니다.

## 구성 요소의 경계

```text
데스크톱 입력 ──→ 게임 명령 ──→ 코어의 게임 상태 ──→ 픽셀 화면
CLI / MCP    ──→ 같은 게임 명령 ──→ 같은 상태 조회
```

위 흐름은 목표 구조입니다. 현재 코어에는 화면 배치와 시간 계산만 있고,
게임 상태와 공통 명령 계층은 다음 단계에 추가합니다.
데스크톱의 사각형 이동은 출력 확인용 데모이며, 아직 CLI로 조작할 수 없습니다.

- `engine-core`: 운영체제·창·네트워크 없이 실행. GPU 없이 테스트 가능.
- `engine-desktop`: 입력을 수집하고 코어 결과를 표시. 게임별 규칙은 장기적으로 포함하지 않음.
- `engine-cli`: 명령을 파싱하고 구조화된 결과를 출력. 게임 규칙을 다시 구현하지 않음.
- 향후 `engine-mcp`: 공식 SDK를 사용하는 얇은 어댑터. CLI와 공통 명령 계층 호출.

## 픽셀과 시간 규칙

1. 기본 논리 화면은 320×180. UI와 효과도 최종적으로 이 영역에 합성합니다.
2. 표시 배율은 `min(창 너비 / 320, 창 높이 / 180)`의 정수 부분입니다.
3. nearest 필터, 중앙 배치, 검은 여백으로 화면 왜곡을 피합니다.
4. 게임 계산은 60틱. 위치 계산에는 소수점을 허용하고 그릴 때 픽셀 좌표에 맞춥니다.
5. 한 프레임에 최대 8틱만 처리하며 긴 정지 중의 오래된 틱은 버립니다.
   실시간 플레이의 멈춤 방지 정책이며, 향후 명시적 `step(n)`에는 이 제한을 적용하지 않습니다.

같은 입력의 재현은 목표지만, 부동소수점 기반 게임의 운영체제 간 완전한 비트 일치는 아직 보장하지 않습니다.
첫 버전에서 3D·범용 ECS·멀티스레드 작업 시스템·스크립트 언어·네트워크 플레이는 도입하지 않습니다.
작은 실제 게임을 만드는 과정에서 필요한 것부터 추가합니다.

## 도구 버전

[Rust 1.99.0 공식 배포](https://blog.rust-lang.org/2026/10/01/Rust-1.99.0/)를 확인해 버전을 지정했습니다.
Macroquad 직접 의존성도 고정했습니다. 전이 의존성은 최초 다운로드 후 생성되는 `Cargo.lock`으로 고정합니다.
지금은 빌드 전이므로 이 조합의 호환성이 검증됐다는 뜻은 아닙니다.
